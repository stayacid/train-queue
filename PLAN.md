# План разработки: «Очередь на поезд» (Z Route Redemption)

Одностраничное приложение, определяющее, чья очередь управлять поездом в игре **Z Route Redemption**.

## Рабочие соглашения

- Коммиты в репозиторий выполняет **только пользователь вручную**. Ассистент не делает
  `git commit` / `git push` — только готовит изменения в рабочем дереве.

## Контекст и правила

- Поезд запускается **раз в день**.
- Офицеры **R3** и **R4–R5** водят поезд по очереди.
- Офицеры **R4/R5** водят поезд по **простой очереди** (по кругу).
- Среди офицеров **R3** за каждую игровую неделю (понедельник 05:00 МСК — воскресенье)
  выбирается **топ-3 по VS**; тройка управляет поездом на **следующей** неделе — по порядку:
  1-й R3-день недели ведёт #1, 2-й — #2, 3-й — #3, 4-й и далее — по кругу (снова #1).

Текст правил (показывается в подсказке, дословно):

> Эта страница показывает, чья сегодня очередь водить поезд. Правила такие:
> - Поезд запускается раз в день
> - Офицеры R3 и R4-R5 водят поезд по очереди
> - Офицеры R4/R5 водят поезд по простой очереди
> - Топ-3 R3 по VS за неделю управляют поездом на следующей неделе по порядку

## Архитектура: Atomic Design

Компонентная структура приложения строится по методологии **Atomic Design** (Brad Frost).
Иерархия зависимостей соблюдается строго: атом не импортирует молекулу, молекула — организм и т. д.;
данные и состояние передаются только «сверху вниз» (страница → организм → молекула → атом) через props.

| Уровень | Что это | Что в проекте |
|---|---|---|
| **Атомы** | Минимальные UI-примитивы, не зависящие от контекста | `RankTag` (бейдж ранга), `SectionTitle` (заголовок секции) |
| **Молекулы** | Сочетания атомов, минимальные законченные функциональные единицы | `HelpButton` (кнопка + popover с правилами), `PagedTable` (таблица + пагинация), `CurrentDriverCard` (блок текущего водителя) |
| **Организмы** | Сочетания молекул, смысловые секции страницы | `TrainQueueHeader` (заголовок + `HelpButton`), `TripJournalTable`, `R4R5ListTable`, `WeekTopR3Table` (заголовок + `PagedTable`) |
| **Шаблоны** | Каркас страницы: раскладка без реального контента | `TrainQueueTemplate` (шапка / центральный блок / три секции) |
| **Страницы** | Шаблон + реальные данные | `TrainQueuePage` (на этапе 1 — моки, на этапе 2 — store) |

Правила:

- Компоненты Element Plus (`el-button`, `el-table`, `el-tag`, `el-popover`, …) считаются готовыми атомами
  UI-кита; собственные атомы — это их тонкая обёртка с конфигурацией под проект.
- Атомы и молекулы **не зависят** от Pinia/store — данные получают только через props.
- Стили — scoped в каждом компоненте; глобальные design-токены (цвета, отступы) — CSS-переменные
  в `src/styles/`.

1. **Заголовок** — слева в шапке, текст **«Очередь на поезд»**, в организме `TrainQueueHeader`.

3. **Центральный блок** — молекула `CurrentDriverCard`: `el-card` по центру страницы с текстом

   (например, `«Василий П.»`). Динамический расчёт — этап 2.
   Ниже — строка **«В прошлый раз управлял(а): {n} день/дня/дней назад»** (`{n}` — целые календарные
   дни от последней поездки этого водителя в журнале; если поездок нет — строка не показывается).
   Если `{n}` меньше порога для ранга — строка **красным** с тултипом по наведению:

   по дизайну ездит примерно раз в неделю). Предупреждение мягкое: не блокирует
   отображение, а подсказывает выбрать другого игрока.
4. **Таблицы** — организмы: заголовок (`SectionTitle`) + молекула `PagedTable`

## Этап 2. Динамический расчёт очереди (завершён)

### Алгоритм: принятые решения

- **Темп**: поезд запускается раз в день. Часовой пояс — **Europe/Moscow**; игровой день
  начинается в **05:00** МСК. «N дней назад» — целые календарные дни (вчера = 1).
- **«Сегодня поездом должен управлять»**: чья очередь сегодня — расчёт по поездкам,
  сделанным **до** текущего игрового дня (журнал без поездок сегодняшнего дня):
  поездка сегодняшнего дня — результат дня, она не влияет на назначение.
  Фактический машинист дня — запись журнала на текущий игровой день; если он
  отличается от назначенного, карточка показывает строку
  «Фактический машинист сегодня: N».
- **Чередование**: строго 1:1 — день R4/R5, день R3, день R4/R5, день R3, …
  Фаза определяется из **последней записи журнала**: последний водитель R4/R5 → сегодня день R3;
  последний водитель R3 → сегодня день R4/R5. День без поездки — очередь просто продолжается
  (чередование сдвигается на поездку, а не на календарный день).
- **R4/R5**: простая очередь (по кругу) по списку R4/R5. Первичный ключ — **позиция в списке**:
  следующий водитель — тот, кто идёт в списке после последнего водителя R4/R5 из журнала.
  Новый R4/R5 (и R3, повышенный до R4) — в конец списка. «Дата последней поездки» используется
  для бутстрапа и самовосстановления после ручной замены (очередь продолжается с того, кто
  реально ездил).
- **R3**: поезд на днях R3 ведут **топ-3 R3 по VS за предыдущую игровую неделю**
  (неделя — с понедельника 05:00 МСК по воскресенье; тройка недели W управляет на неделе
  W+1), **по порядку**: 1-й R3-день недели → #1, 2-й → #2, 3-й → #3, 4-й и далее —
  по кругу (снова #1). «R3-день недели» — порядковый номер R3-поездки в журнале за
  текущую игровую неделю (первая поездка — 1-й день и т. д.). Равенств нет — список
  нумерует сама игра. Если за прошлую неделю топ-3 не найден — берём ближайшую
  предыдущую неделю (до 52 недель назад); если и её нет — водитель не определяется
  (null, в UI — подсказка заполнить вкладку «Топ3 R3»).
  Таблица «Лидеры R3 по VS» показывает все строки вкладки «Топ3 R3» (неделя,
  место, никнейм); тройка, управляющая поездом на текущей неделе, — это тройка
  за предыдущую неделю.
- **Кулдаун**: офицер, управлявший меньше порога для ранга, — на кулдауне:
  R4/R5 — `MIN_DAYS_R4R5` (= 14, «максимум раз в 2 недели»: при списке из N цикл ротации
  ~2N игровых дней, поэтому предупреждение горит только при сжатом цикле или поездке
  вне очереди), R3 — `MIN_DAYS_R3` (= 10, тройка недели по дизайну ездит примерно раз
  в неделю). Это **мягкое предупреждение** для обеих групп (красная строка + тултип в
  `CurrentDriverCard`), не блокировка. Внутри тройки R3 авто-фолбэк **есть**: если
  назначенный по слоту на кулдауне, поезд ведёт следующий доступный из тройки по порядку;
  если все трое на кулдауне — назначенный (человек видит предупреждение и решает).
  Для R4/R5 авто-фолбэка нет: решение принимает человек.
- **Отсутствие / ручная замена**: обрабатываются вручную — в журнал записывается тот, кто
  реально ездил, очередь продолжается от него (самовосстановление по позиции в списке).
- **Бутстрап**: начальное состояние (фаза чередования, указатель очереди) считается из
  журнала поездок. Пустой журнал → считаем сегодняшний день днём R4/R5 (старт цикла).
- **Источник данных**: Google Sheets (этап 3).
